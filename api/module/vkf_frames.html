Reference frames: the tree of frames that every scene object belongs to, as OpenFrames' ReferenceFrame.

A frame has a position and attitude relative to its parent, a color for its decorations (axes, labels), and children. It can follow trajectories (follow), which then set its position and/or attitude at each update. Scene objects (spheres, models, trajectories' artists, ...) extend this type.

Frames are owned by the program, not by the tree: add_child stores pointers, so a frame (declared target, or allocated) must stay alive while it is in a tree, or be removed first (detach). A frame may have several parents; adding a child that is an ancestor of the parent is refused.

Rendering: when a window first shows a tree (realize), each frame gets a transform node, with its contents (build_contents, which extensions override) under a switch for show_contents; children's nodes go under the parent's transform, so a frame with several parents is drawn under each. Each frame, update moves followed frames to the time, then late_update lets contents depend on other frames' positions at that time (e.g. CustomLineSegments between spacecraft), and sync copies positions and attitudes to the transforms. A shown tree can change: children added to a shown frame are realized and compiled (for the windows running) and drawn from the next frame; removed ones stop being drawn; moved axes (move_x_axis, ...) are made again.

Labels: the name label (at the origin, facing the screen) and the axes' labels can change while shown: the name (set_name, e.g. a readout that follows the frame), color, label size, alignment and font, and the axes' label texts.

Picking (WindowProxy%pick): each frame tests what it draws against a PickCamera (vkf_pick) in its pick procedure, given its transform to the root frame, and adds a PickHit for each thing within reach (the window sorts them nearest first). A plain frame is picked at its origin if it shows axes or its name label (PICK_FRAME); extensions pick their contents (bodies, trajectories).
