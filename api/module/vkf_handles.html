Handles (not in OpenFrames): things in the scene the mouse drags, to design graphically, e.g. a trajectory's initial position and velocity.

A DragHandle is a frame with a point the mouse can grab (handle_point, in the frame's coordinates) and move (move_handle_point); extensions say what the point is and how they are drawn. Windows drive them (WindowProxy, see vkf_window): the handle under the cursor is hovered (drawn brighter); a left button press on it grabs it (the camera stays where it is: the trackball doesn't see the press), the mouse's moves drag it, and the release lets it go. The window's event handler is told (handle_drag, with DRAG_START, DRAG_MOVE and DRAG_END), e.g. to compute a trajectory again from the new state while the handle is dragged. Handles can also be moved by the program (VectorHandle%set_vector), and dragged by it (grab, drag and release, given the cursor's ray).

Where the point goes is where the cursor's ray (WindowProxy%cursor_ray) meets the handle's constraint (set_constraint), as it was when the handle was grabbed, plus the point's offset from the cursor then (so the point doesn't jump to the cursor): * HANDLE_FREE (the default): the plane through the point facing the camera; * HANDLE_PLANE: the plane through the point with the normal given; * HANDLE_LINE: the line through the point along the direction given; * HANDLE_RADIAL: the line from the frame's origin through the point (e.g. a vector's length only); * HANDLE_SPHERE: the sphere about the frame's origin through the point (e.g. a vector's direction only), on the side (near or far, from the camera) where it was grabbed; where the ray misses it, its edge nearest the ray. Normals and directions are in the frame's coordinates. A ray parallel to a plane or a line doesn't move the point. Positions go through the frames' first parents to the root (ReferenceFrame%world_matrix).

Handles on the same spot of the screen (e.g. a trajectory's end marker on its state's arrow): the window hovers the one nearest the cursor on the screen; within a few pixels of each other, the one of the highest priority (set_priority; markers, TimeHandle, 1 by default, before arrows, 0), then the nearest to the eye.

A VectorHandle is an arrow from its frame's origin to its tip, the tip being the handle: a vector (set_vector, in the frame's coordinates) times a display scale (set_display_scale: e.g. 1000 s to draw a velocity in km/s as km). Dragging the tip changes the vector. The arrow is in the frame's color, lit as frames' axes (by how it faces the viewer); its head is set_head_size long (scene units; default 0.2 of the arrow, at most half of it). It is built once, as a unit shaft and head scaled and turned by two transforms: a new vector only sets them (cheap enough for every frame of a drag).

A TimeHandle is a marker at a time along a path (a TimePath: a position for any time, in the coordinates of the handle's parent frame, e.g. a propagator's), dragged along the path to change the time: e.g. a trajectory's end, dragged to make it longer or shorter in time. The path needn't be drawn where the handle goes (beyond a trajectory's last point, the program propagates further). The frame is placed at the path's position for the time (set_time), so its name label (e.g. the time, set_name) goes with it; the marker is the size of MarkerArtist's markers (window units, not shrinking with distance). A drag takes the time within set_time_range whose point is nearest the cursor's ray (as seen from the eye): among the path's points sampled at the grab, then refined between them; where the path passes near itself (orbits), the match nearest in time to the handle's time is taken, so it doesn't jump to another revolution. A TrajectoryPath follows a Trajectory's points (interpolated linearly), within its times.
